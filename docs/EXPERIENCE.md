# Experience principle

**Infer early. Recommend sensible defaults. Reveal detail progressively. Keep choices editable.**

Everyone uses the same process. Tailor the controls immediately visible to their
goal and comfort level; offer **Show all controls** from the start.

- Detect context before asking. Ask when evidence is missing or ambiguous.
- Lead with the next action, its consequences and its result.
- Recommend defaults; let users inspect and change them before applying.
- Reveal explanations and technical controls when relevant. Switching views
  preserves edits and never starts an operation.
- Explain failures with a next step; keep codes and logs underneath. Unknown
  failures need investigation, not an automatic retry.

Fresh setup recommends the browser remote, automatic Standard Mode and
**Remote admin access** with a chosen password for future updates without USB.
Existing toolkit settings win. Older standalone setups use an explicit clean
replacement with new settings. Formatting and installation require user action.

Documentation follows the same layers: outcome first, relevant instructions next,
reference on demand. Ask of every screen or paragraph: **does this help the user
decide, act or understand the result now?** If not, move it deeper.
